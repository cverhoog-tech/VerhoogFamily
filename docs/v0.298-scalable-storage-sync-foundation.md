# v0.298 — Scalable Storage & Sync Foundation

Status: TODO / architecture foundation
Priority: High
Branch: feature/v0.271-group-quests

## Product decision

FamilyApp must become scalable for real household use.

That means:

- shared data must not rely on local-only state
- uploaded images must not stay as permanent data-URLs in task data
- household/member permissions must be part of every shared entity
- live sync must be checked module by module
- legacy array data must be mapped toward explicit object models

## Current risk areas

### 1. Task photos

Current MVP behavior:

- quest/task create supports custom photo upload
- uploaded image is compressed
- image is stored inside task image field as data-URL

This is acceptable for testing but not scalable.

Production direction:

```js
{
  imageUrl: "https://...",
  imageStoragePath: "households/{householdId}/tasks/{taskId}/cover.webp"
}
```

Keep data-URL fallback during migration.

## Storage provider decision

Recommended first path: Firebase Storage, because Firebase/household sync already appears to be part of the project direction.

Before implementation, verify current free-tier constraints and current project setup.

Alternatives:

- Supabase Storage + Postgres + Realtime
- Cloudinary for images only

Decision rule:

- If Firebase project is already active and free tier is enough: use Firebase Storage first.
- If we need a cleaner relational backend and are willing to migrate data models: evaluate Supabase.
- Use Cloudinary only if image transformations become the main concern.

---

## Storage path convention

Use predictable household scoped paths:

```txt
households/{householdId}/tasks/{taskId}/cover.webp
households/{householdId}/recipes/{recipeId}/cover.webp
households/{householdId}/avatars/{memberId}.webp
households/{householdId}/feed/{postId}/{imageId}.webp
```

Rules:

- compress before upload
- max upload size client-side
- store only URL/path in shared data
- never store large base64 images permanently in database
- keep old data-URL fallback while migrating
