# v0.298a — Sync Audit: Taken module

Status: TODO / audit started
Priority: High
Parent: v0.298 — Scalable Storage & Sync Foundation

## Scope

This audit focuses on the Taken module because it now contains the most important shared household interactions:

- task creation
- custom task photo upload
- Vraag om hulp
- helper join/leave
- subtasks/checklists
- recurring tasks
- person/member task views
- task swap/ruilen flows
- XP/rewards/progression hooks

## Product direction

The separate Group tab is removed. Collaboration must live inside normal tasks.

Correct flow:

```txt
Shane creates a task
Shane requests help
Esra sees the help request live
Esra joins
Shane sees Esra joined live
The task/activity state stays consistent after refresh and on both devices
```

## Known risks

### 1. Legacy task array model

Tasks are still partly represented as arrays.

Known index usage from current patches:

```txt
task[0]  id
task[1]  type
task[2]  title
task[3]  description
task[4]  dueDate
task[5]  assignedTo
task[6]  xpReward
task[7]  image/photo
task[8]  subtasks
task[9]  progress/completed count
task[10] recurrence
task[11] recurrence/date helper
task[12] priority
task[13] helpRequested
task[14] helpers
```

Risk:

- fragile
- easy to break with new features
- hard to sync granularly
- hard to enforce permissions

Required fix:

- introduce `TaskAccessors` or `TaskModel` layer
- no new module should read/write raw array indexes directly
- map legacy arrays to normalized objects

Target object:

```js
{
  id,
  householdId,
  title,
  description,
  type,
  priority,
  dueDate,
  assignedTo,
  createdBy,
  updatedBy,
  imageUrl,
  imageStoragePath,
  imageDataUrlFallback,
  helpRequested,
  helpers,
  subtasks,
  status,
  xpReward,
  recurrence,
  createdAt,
  updatedAt
}
```

---

### 2. Photo upload is not production storage yet

Current:

- compressed base64/data-URL is stored in task image field

Problem:

- shared DB payload gets large
- sync becomes slower
- not scalable for many tasks/households
- harder to cache and clean up

Required fix:

- add real storage service
- upload image to Firebase Storage or chosen provider
- save URL/path on task
- keep data-URL fallback only when storage unavailable

Target fields:

```js
imageUrl
imageStoragePath
imageDataUrlFallback
```

---

### 3. Live sync must be verified, not assumed

The current modules attempt to use:

```txt
TaskRepositoryAdapter
HouseholdRepository
familyapp:tasks-updated events
localStorage fallback
```

But this does not automatically prove multi-device live sync works.

Required test:

```txt
Device A: Shane creates task
Device B: Esra sees task without manual refresh
Device A: Shane requests help
Device B: Esra sees Hulp gevraagd
Device B: Esra joins
Device A: Shane sees Esra joined
Both devices refresh and state remains correct
```

If this fails, the problem is in repository/live sync layer, not UI.

---

### 4. Activity log is not yet standardized

Current patches may call `addActivity()` or repository append activity when available.

Risk:

- inconsistent event shapes
- duplicated events
- not all actions visible in feed/activity

Required fix:

- central `ActivityService`
- fixed event types
- every shared action writes standard activity event

Task event types:

```txt
task.created
task.updated
task.deleted
task.help_requested
task.helper_joined
task.helper_left
task.subtask_completed
task.photo_uploaded
task.recurring_completed
task.swap_requested
task.swap_accepted
```
